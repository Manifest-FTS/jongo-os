## Safe isolated preview and draft workflow

Use the [local verification runbook](cms-local-verification.md) for exact commands and separation of offline verification, browser review, dry-run and explicit apply. **Do not run production migration/seed/reset/tunnel wrappers for this workflow. Loopback alone is not proof of a disposable target.**

1. Obtain separate approval for local setup. A real isolated authentication database, compatible generated Prisma client, reviewed migrations/tables, actual user, organization and dataset are prerequisites. **Dataset provisioning/grant-management UI does not exist.** No command in this guide creates a dataset, a paid sponsor or credentials; do not guess an ID or synthesize financial grants.
2. Set server-only `JONGO_CMS_ENABLED=true` for reads/schema preview. Private saves/import apply additionally require **`JONGO_CMS_WRITES_ENABLED=true`**, both exact strings, default off. Restart the isolated server after changing its environment. Never use `NEXT_PUBLIC_` variants or enable production flags under this task.
3. Sign in normally. The organization's actual persisted owner must have an active, unexpired Studio/Scale subscription for authoring; stored IDs remain `core-sla`/`enterprise-sla`. Trialing, missing/deleted sponsors and unknown/inactive/expired states deny writes. A collaborator's purchase, receivables status, super-admin/technical/bootstrap role is no substitute.
4. `/clients/<clientId>/content` is still the local-only five-schema preview. `/clients/<clientId>/content/<datasetId>` is the implemented private dataset list, showing the first bounded page (up to 100 metadata rows, filtered to drafts). `?type=<registeredType>` opens a new draft; `?docId=<documentUuid>` opens an existing exact draft. IDs must be real isolated records; the dataset must belong to that client.
5. Use sanitized non-sensitive sample fields and **Save draft** on the dataset editor. Nested objects/arrays/Portable Text still use JSON textareas, not full visual controls. Save never publishes. Success advances native CAS; conflict retains inputs and requires reviewing the latest revision. A lost-response retry reuses the unchanged request/receipt identity. **No draft-delete operation exists.**
6. Reopen the saved document to check persistence independently; verify read-only/denied behavior after flag or entitlement removal. This manual browser exercise is separate from the verifier and has not been performed by this docs update. Restore both flags to off after review. No CMS delivery/media key is needed for this slice; future secrets belong in an approved secret channel, never chat.

## Policy and validation boundaries

- Organization schema preview: owner or live organization admin/collaborator may read descriptors; author/customize capacity is owner-only Studio/Scale (Scale for customization). Site-only membership is not organization access. Preview capacity does not itself authorize dataset writes.
- Dataset policy: owner/live org admin have admin baseline; org collaborators start reader and may receive explicit elevated grants. Site-only members need a live grant for the exact linked dataset. A grant without live tenant membership is insufficient; standalone datasets confer no site-only access.
- Dataset read/export capability survives sponsor downgrade when tenant relationship remains valid; edit needs editor+, publish publisher+, management admin, intersected with actual owner capacity. These export/publish/manage/customize bits are **not implemented endpoints**. Repository/action/import apply independently recheck write authority and both flags.
- `InferDocument` models descriptor literals, not runtime bounds, URL/date safety, reference existence, key uniqueness, consent or cross-field proofs. Reference types are generic; Portable Text has broad JSON alternatives. `publishRequired` remains optional in authoring types. Runtime validation is mandatory.
- Structural `canPublish` is not verified consent, authorization or a release. Preview has no bound reference picker/record map or ICU parser; dictionary placeholder contracts require code-owned context. Unknown/quarantined structures cannot be saved as native drafts; importer quarantine is report-only, leaving original private source in place.
- Stripe reconciliation is implemented but not production-accepted: canonical retrieval/dedup/state/user changes commit together under the owner `FOR UPDATE` lock, conflicting with CMS `FOR SHARE`. Fresh writes lock out after persisted downgrade/cancellation **once the event is accepted into the application DB**, not instantly when Stripe changes. Provider/storage failure rolls back without a completion receipt and returns retryable failure; no outage-time freshness or instant-propagation promise. See [billing persistence](cms-persistence.md#stripe-subscription-events--implemented-not-deployed).
