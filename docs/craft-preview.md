## Boundary and package audit

The upstream repository had no craft directory or public Craft export. CMS modules are app-local: `apps/web/src/lib/cms/schema.ts` uses JSON `TypeDefinition` documents, `schemaVersion`, bounded fields and a frozen registry; `schemas.ts` registers content types. The independent `craft/` package uses compatible **content-only** descriptors for notice/help copy. It does not import Jongo's auth, billing entitlements, Prisma or operations shell. Descriptors are not registered automatically, nor does the package claim upstream validation or CMS persistence.

`@jongo/craft` exports a typed generic `CraftPlugin<T>` / `CraftContext<T>` shell, role-visible views, identity/data injection and shared Button, Badge, Card and native modal Dialog. `@jongo/craft/golf-lab` exports the extension, demo, specimens, schema descriptors and fixture factory. `@jongo/craft/logic` exports pure business logic. Import `@jongo/craft/styles.css` explicitly. All selectors are scoped under `.craft-root`; no homepage/global styles are changed. React/React DOM 19 are peer dependencies. Compiled ESM JavaScript, declarations and CSS are included in the packed artifact. No runtime framework or backend dependency.

## Source, tests and reproducible delivery

Run `npm ci --ignore-scripts`, `npm test` and `npm pack` from `jongo/craft`. This package is deliberately independently installable, not added to the Jongo root workspaces; root install/postinstall/migration scripts are unnecessary.

From the website, `npm run craft:repack` installs locked package development dependencies, tests, builds, packs into the website vendor directory, and refreshes the exact file-tarball dependency and lockfile. Only this authoring command needs the sibling checkout. Sources are edited in `jongo/craft`, never the installed copy. For a new release, bump the package manifest/lock version; the script derives the artifact filename without a script edit. Review and retain the generated tarball and website package lock together.

Deployment needs **only the website checkout**, including `vendor/jongo-craft-0.1.0-preview.1.tgz`, package manifest and lockfile: run `npm ci` then `npm run build`. No sibling path, private registry, git credentials or package build tool is required. Do not ignore or omit vendor from the deployment context. The npm lock records artifact integrity.

Website verification commands: `npm run test:craft` exercises installed exports, generic shell injection, role-scoped server rendering and specimens. After a website build, `npm run test:craft:http` starts loopback-only servers and checks all seven entry routes plus an unknown route with unset/false/uppercase/exact-true flags (32 checks). `npm run test:craft:isolated` copies only public source/config/assets and the vendor artifact into an unrelated temporary directory, runs a clean install/build, then cleans up. It never copies environment/secret files or the Jongo checkout.

`CRAFT_PREVIEW_ENABLED=false` is the documented default. Unset, false, uppercase or any value other than exact server-side `true` returns 404 for every `/craft` path. The dynamic route evaluates it on each request and exports noindex/nofollow metadata. Set exact `true` **only on an approved isolated preview host**; this is a rollout switch, not authentication. Anyone reaching an enabled preview can switch fictional roles. Hosting-level access control is a separate deployment responsibility. This task does not verify or change deployment webhooks.

Entry points: `/craft`, `/craft/member`, `/craft/booking`, `/craft/admin`, `/craft/instructor`, `/craft/reports`, `/craft/billing`. Unknown/nested routes return 404. The style guide is an existing public noindex design document; new static specimens are labeled proposed/not approved, link to gated routes and contain no operational adapters or real data.

## Demo review and limitations

- Fixed clock: November 2, 2026 at 08:00 America/Chicago. All data is fictional; changes live in React memory and reset on reload/reset. Role controls demonstrate UI permissions, not server security. No payment, mail, production, persistence, authentication or database calls.
- Member accounts demonstrate active Individual, Family, approved Junior, suspended access and missing waiver. Individual advance 7 days; Junior 1 day; winter Nov–Apr 1h/day, summer May–Oct 2. Family requires Individual. Four bays. Member calendar labels others as occupied, not their identity. Admin can book for accounts but cannot bypass member quota/waiver checks.
- Whole-hour slots, 1–2h within one local day. Chicago DST ambiguous/gap/cross-offset bookings are rejected rather than silently shifted. No overnight reservations, partial hours or attendance. Backend must enforce transactional overlap/quota constraints before real use.
- Instructor 90-day window and 2h event ceiling are explicit **proposed** review policies, not approved website entitlements. Instructors see/manage only their own booking details, no directory/reports. Weekly series are finite 2–8 occurrences; every date is previewed, conflicts block commit unless explicitly skipped, and all-conflicted creates nothing. Editing/cancellation affects one occurrence only; whole-series edit/cancellation UI is deferred.
- Directory/details and weekly/monthly member/instructor filtering + CSV are admin-only UI. Reporting uses local date ranges, exclusive period end and mutually exclusive booked/completed/cancelled scheduled hours. Completed means end passed the fixed clock, not actual attendance. Cancelled hours never count completed. No rates, manual hour adjustments or metered invoices.
- Checkout has canonical $199 monthly/12-month commitment, $2,199 annual upfront, $289 flexible monthly, $85 family monthly prerequisite and $1,800 annual approval-required Junior. Demo agreement version is illustrative, not a legal waiver or signature. Simulated success/decline creates no subscription or entitlement. Sponsor/approval checkboxes simulate prior server verification, never production self-approval. Billing cancellation is a request; commitment, fees, refunds and effective dates need final policy. Admin leave review records only an in-memory proposal/reason; billing, access, extension and provider reconciliation remain separate unresolved production work.
- Native `dialog.showModal()` supplies focus containment, inert background, Escape dismissal and restoration. Scoped reduced-motion styles and single-bay mobile list are included. Browser/assistive technology acceptance is distinct from unit/build verification.
- No production readiness claim: real identity, authorization, privacy, transactions, audit storage, waiver legal review, provider webhooks, durable notifications, deployment isolation and full accessibility/security acceptance remain future milestones. No SMS, attendance, manual hour overrides, rates, migrations or live billing integration.
