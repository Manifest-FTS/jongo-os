# Craft / Golf Lab initial preview

## Current refinement — preview.7 Sanity-style content studio, 2026-11-04

`/craft` stays a neutral Jongo-branded content studio in its own `jongo-studio` CSS namespace (no Golf Lab green theme, no `craft-root` shell). `/admin` and `/portal` operational fixtures, the exact default-off server gate/noindex, routes and billing/scheduling behavior are unchanged. No commits/pushes, deployment, DB/migrations, secrets/environment reads or provider/network calls. Content only; no operational records.

**Documents** now use Sanity-shaped envelopes at top level (`{ _id, _type, ...fields }`). The earlier flat `{id,type,title,values}` shape and `validateContent` were removed (a breaking change for any consumer of preview.6; the website seed content and tests were migrated). Local-draft semantics are retained and extended: an **original snapshot** (supplied documents with missing/duplicate `_key`s filled deterministically), a **saved local draft**, **unsaved changes** (dirty state), *Reset changes* (to the last saved draft) and *Revert to original snapshot*. The page states that persistence and publishing are not connected; nothing is saved or published.

**Field types** (descriptor names/shapes follow `apps/web/src/lib/cms/schema.ts` so schemas stay portable; nothing is imported from `apps/web`): `string`, `text`, `number` (min/max/integer), `boolean`, `date`, `datetime` (entered and stored as UTC), `url`, `slug` (`{_type:'slug', current}` with optional *generate from* source field), `enum`, `object` (nested fields, optional `objectType`), `array` (primitives, objects or references/images; min/max, up/down reorder, add/remove, stable `_key` on object-like items), `reference` (`{_type:'reference', _ref, _weak?}`, searchable picker over supplied documents of the allowed types, shows the target title, always the logical ID without `drafts.`), `image` (`{_type:'image', asset:{_type:'reference',_ref}, alt, caption}`, picks from supplied `sanity.imageAsset` documents; **no upload**) and `portableText`. `required`, `publishRequired` and `private` flags are honored as in the upstream descriptors (`private` is a visible label only, not access control). Craft-only additions, not present upstream: the `image` descriptor, `slug.source`, `reference.weak`, `image.altRequired`, `schema.preview.title`. Upstream's `asset` descriptor, named `rules` and `keyed` flag are not supported.

**Portable Text editor** (bounded, no `contentEditable`, no HTML): ordered blocks with style (normal, h2, h3, h4, blockquote), list type and level (1–10), a textarea per block, bold/italic/code applied to the textarea selection (`selectionStart`/`selectionEnd`), link annotations with an editable web address, and block add/move/remove. Spans are split on the selection, the first fragment keeps its `_key`, adjacent spans with identical marks are merged, typing inherits neighbouring marks, and links are only extended when typing inside one. Unknown block types, unknown styles/list types, marks, annotations, extra fields and blocks with inline objects or rich spans are never rewritten: non-text blocks appear as read-only *Preserved block* entries with their JSON, and text blocks carry unknown fields/marks/markDefs through every edit. A user may still deliberately remove or reorder a preserved block. Only link definitions the editor itself unlinks are pruned. Missing/duplicate PT keys are filled deterministically on load.

**Validation** (`validateDocument`, pure) covers required, min/max length, number bounds/integer, URL safety (http/https/mailto/tel/relative/#), valid calendar dates and UTC timestamps, enum membership, slug format, array min/max and unique keys, reference existence/allowed type/no `drafts.` prefix (weak references may dangle as a warning), image asset and optional alt text, and Portable Text structure. Unregistered fields, unknown PT blocks/marks/styles/annotations are *warnings* about preserved content. Errors show inline (`aria-invalid` + `aria-describedby` to a per-field list) and in a document summary whose entries jump to the field. A draft with errors can still be saved locally; the **publish-ready indicator** is blocked while any error exists. It reflects local schema checks only; there is no publish action.

**Keyboard/accessibility**: labels for every control, `fieldset`/`legend` for objects, arrays, references, images and Portable Text, focus moved to the new/next item after add, remove and reorder, a single polite live region announcing changes, the shared native `Dialog` for reference/image pickers (focus in the search box, Escape closes, focus returns to the opener) and a single-column layout without horizontal overflow at 360/390/768/1440. Studio-scoped CSS now styles that Dialog inside `.jongo-studio` (the Craft shell stylesheet is not loaded on `/craft`). This is not full assistive-technology certification.

**Website**: `dd-thegolflab/src/lib/craft-content.ts` models Golf Lab content in this style, studio only; no live site component reads it. Homepage (title, slug, search description, hero reference, section references, image gallery), hero (copy copied from the current `PreviewGate.tsx`), How It Works (steps array of `{title,text,icon}`, icons limited to the four actually used: users, clock, chart, target), facility copy (the five current facility paragraphs as Portable Text, last one bold; heading and accent image) and global config (business name, optional empty phone, address lines and Instagram URL from `src/lib/business.ts`). Tests assert these strings against the live source file. Asset library documents point to existing `/assets/...` files.

Package structure: pure modules `schema.ts`, `portable-text.ts`, `content-ops.ts`, `validate.ts` (also exported as `@jongo/craft/content`), and React `fields.tsx`, `portable-text-editor.tsx`, `studio-context.tsx`, `studio.tsx`. Artifact `@jongo/craft@0.1.0-preview.7` created by `npm run craft:repack`; older tarballs (preview.1–6) and unrelated manifest entries are preserved.

Verification, run 2026-11-04: **89 package tests** (new: 10 Portable Text, 15 content/validation/SSR, plus migrated studio tests), **32 website consumer tests**, **201 HTTP gate/route checks** (production build, own random ports), production build/TypeScript, website-only isolated clean install/build, and the Playwright Chromium workflow (own server, external requests blocked) including the new studio scenario: array item edit, reorder with focus retention, add/remove, Portable Text bold and link on a real keyboard text selection, block add/reorder/remove, reference and image pickers, alt-text and required-field errors with summary jump, invalid local save, reset, snapshot revert, reload reset and no overflow at 360/390/768/1440. Screenshots were reviewed; zero browser JS errors.

Limits and unverified: no persistence, authentication, authorization, publishing, media upload or revision history; documents are not native Jongo documents (`_rev`/`_createdAt`/`_updatedAt` are tolerated but not managed), and there is no connection to the Jongo registry, publication or storage code. Not Sanity Studio parity: no real-time collaboration, GROQ/preview, validation callbacks, conditional/hidden fields, custom inputs, image crop/hotspot UI, inline (span-level) objects, nested lists beyond a level number, rich paste or drag-and-drop ordering. Portable Text text editing uses a plain textarea, so formatting is shown in a preview line rather than in place; IME and screen-reader behavior of selection-driven formatting is untested. Datetime inputs are UTC-only. Safari/Firefox, mobile devices and full assistive-technology use are untested. Existing website audit unchanged (21 findings); Craft audit not re-run.

## Boundary and package audit

The upstream repository had no craft directory or public Craft export. CMS modules are app-local: `apps/web/src/lib/cms/schema.ts` uses JSON `TypeDefinition` documents, `schemaVersion`, bounded fields and a frozen registry; `schemas.ts` registers content types. The independent `craft/` package uses compatible **content-only** descriptors for notice/help copy. It does not import Jongo's auth, billing entitlements, Prisma or operations shell. Descriptors are not registered automatically, nor does the package claim upstream validation or CMS persistence.

`@jongo/craft` exports a typed generic `CraftPlugin<T>` / `CraftContext<T>` shell, role-visible views, identity/data injection and shared Button, Badge, Card and native modal Dialog. `@jongo/craft/golf-lab` exports the extension, demo, specimens, schema descriptors and fixture factory. `@jongo/craft/logic` exports pure business logic. Import `@jongo/craft/styles.css` explicitly. All selectors are scoped under `.craft-root`; no homepage/global styles are changed. React/React DOM 19 are peer dependencies. Compiled ESM JavaScript, declarations and CSS are included in the packed artifact. No runtime framework or backend dependency.

## Source, tests and reproducible delivery

Run `npm ci --ignore-scripts`, `npm test` and `npm pack` from `jongo/craft`. This package is deliberately independently installable, not added to the Jongo root workspaces; root install/postinstall/migration scripts are unnecessary.

From the website, `npm run craft:repack` installs locked package development dependencies, tests, builds, packs into the website vendor directory, and refreshes the exact file-tarball dependency and lockfile. Only this authoring command needs the sibling checkout. Sources are edited in `jongo/craft`, never the installed copy. For a new release, bump the package manifest/lock version; the script derives the artifact filename without a script edit. Review and retain the generated tarball and website package lock together.

Deployment needs **only the website checkout**, including `vendor/jongo-craft-0.1.0-preview.1.tgz`, package manifest and lockfile: run `npm ci` then `npm run build`. No sibling path, private registry, git credentials or package build tool is required. Do not ignore or omit vendor from the deployment context. The npm lock records artifact integrity.

Website verification commands: `npm run test:craft` exercises installed exports, generic shell injection, role-scoped server rendering and specimens. After a website build, `npm run test:craft:http` starts loopback-only servers and checks all seven entry routes plus an unknown route with unset/false/uppercase/exact-true flags (32 checks). `npm run test:craft:isolated` copies only public source/config/assets and the vendor artifact into an unrelated temporary directory, runs a clean install/build, then cleans up. It never copies environment/secret files or the Jongo checkout.

`CRAFT_PREVIEW_ENABLED=false` is the documented default. Unset, false, uppercase or any value other than exact server-side `true` returns 404 for every `/craft` path. The dynamic route evaluates it on each request and exports noindex/nofollow metadata. Set exact `true` **only on an approved isolated preview host**; this is a rollout switch, not authentication. Anyone reaching an enabled preview can switch fictional roles. Hosting-level access control is a separate deployment responsibility. This task does not verify or change deployment webhooks.

Entry points: `/craft`, `/craft/member`, `/craft/booking`, `/craft/admin`, `/craft/instructor`, `/craft/reports`, `/craft/billing`. Unknown/nested routes return 404. The style guide is an existing public noindex design document; new static specimens are labeled proposed/not approved, link to gated routes and contain no operational adapters or real data.

## Demo review and limitations

- Fixed clock: November 2, 2026 at 08:00 America/Chicago. All data is fictional; changes live in React memory and reset on reload/reset. Role controls demonstrate UI permissions, not server security. No payment, mail, production, persistence, authentication or database calls.
- Member accounts demonstrate active Individual, Family, approved Junior, suspended access and missing waiver. Individual advance 7 days; Junior 1 day; winter Nov–Apr 1h/day, summer May–Oct 2. Family requires Individual. Four bays. Member calendar labels others as occupied, not their identity. Admin can book for accounts but cannot bypass member quota/waiver checks.
- Whole-hour slots, 1–2h within one local day. Chicago DST ambiguous/gap/cross-offset bookings are rejected rather than silently shifted. No overnight reservations, partial hours or attendance. Backend must enforce transactional overlap/quota constraints before real use.
- Instructor 90-day window and 2h event ceiling are explicit **proposed** review policies, not approved website entitlements. Instructors see/manage only their own booking details, no directory/reports. Weekly series are finite 2–8 occurrences; every date is previewed, conflicts block commit unless explicitly skipped, and all-conflicted creates nothing. Editing/cancellation affects one occurrence only; whole-series edit/cancellation UI is deferred.
- Directory/details and weekly/monthly member/instructor filtering + CSV are admin-only UI. Reporting uses local date ranges, exclusive period end and mutually exclusive booked/completed/cancelled scheduled hours. Completed means end passed the fixed clock, not actual attendance. Cancelled hours never count completed. No rates, manual hour adjustments or metered invoices.
- Checkout has canonical $199 monthly/12-month commitment, $2,199 annual upfront, $289 flexible monthly, $85 family monthly prerequisite and $1,800 annual approval-required Junior. Demo agreement version is illustrative, not a legal waiver or signature. Simulated success/decline creates no subscription or entitlement. Sponsor/approval checkboxes simulate prior server verification, never production self-approval. Billing cancellation is a request; commitment, fees, refunds and effective dates need final policy. Admin leave review records only an in-memory proposal/reason; billing, access, extension and provider reconciliation remain separate unresolved production work.
- Native `dialog.showModal()` supplies focus containment, inert background, Escape dismissal and restoration. Scoped reduced-motion styles and single-bay mobile list are included. Browser/assistive technology acceptance is distinct from unit/build verification.
- No production readiness claim: real identity, authorization, privacy, transactions, audit storage, waiver legal review, provider webhooks, durable notifications, deployment isolation and full accessibility/security acceptance remain future milestones. No SMS, attendance, manual hour overrides, rates, migrations or live billing integration.
